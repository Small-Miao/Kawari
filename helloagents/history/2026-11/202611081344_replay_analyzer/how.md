# 技术设计

## 方案选择

比较本地网页、WinForms、WPF：采用 .NET 10 WinForms 独立桌面程序，复用已安装的 WindowsDesktop 运行时，不新增第三方包。核心解析库和命令行测试独立于界面，可在持续集成中运行。源码放 tools/ReplayAnalyzer，发布到 target/ReplayAnalyzer。

## 分层

- Core：FFXIVREPLAY v5 有界解析、协议版本配置、匿名演员索引、动作效果解码、CSV 资源表、关联分析、阶段和合并、工程与报告。
- Desktop：原生中文窗口，虚拟事件表、时间轴、技能关联、阶段合并、物件/资源、筛选、阶段及分类编辑。
- Tests：二进制边界和语义回归、合并/工程 roundtrip、真实录像全量扫描。

## 证据约束

- 原始包中的伤害、治疗、状态、击退等作为观察到的结算；未知效果类型单独标注。无伤害不等于纯演出。
- 读条中的技能 ID 和动作效果同源关联优先；跨 Helper 或 MapEffect 只靠时间接近时标为候选，不宣称因果。
- CSV 的 Omen / ActionTimeline / VFX 引用属于资源配置证据，不等于客户端确认播放。列类型校对避免旧 CSV 表头错位。
- 原始章节用于尝试/过场标记；已核对的五个最终阶段只按录像 SHA 匹配预设。其他阶段为候选，可编辑，不能假称自动识别 P1/P2。
- 合并按副本、客户端版本、阶段名称和时间锚点分组，保留不同录像/尝试与时间误差，不能把单次重复调用折叠掉。

## 安全与性能

原始录像只读；忽略录制者 CID、玩家名称，不展示聊天；未知包保留统计。后台可取消分析，表格虚拟化，默认过滤玩家动作及高频移动。JSON 工程只存路径、调整和人工标记，不改服务器，不执行导出数据。

## 单独机制整理

增加 `Mechanics.cs`，在相同副本、build 和阶段名称内按中文技能名归组，保留多个技能 ID、全部原始调用和各自关联证据。通用/未知名称按 ID 区分；人工机制名称存入工程的 EventAnnotation，不覆盖原始技能 ID。界面追加“机制分组 · 多录像”，支持多选合并、双击只看单独机制、单组 JSON 和分组 CSV。沿 NPC Owner 链过滤召唤物，仅过滤玩家技能，Boss 施加给玩家的状态仍可分析。

发布 1.1.0 至 `target/ReplayAnalyzer-1.1.0`，保留用户已打开的 1.0 窗口，避免覆盖运行中的程序或丢失其未保存编辑。
