# 设计

## 选择

采用每副本独立 C# 子进程，通过标准输入输出 JSON 帧连接 Kawari。相比嵌入 CLR，脚本死循环或异常不会阻塞世界服；相比直接连接现有卫月模拟协议，可以保持真实实体、HP、Buff 和任务取消的一致性。复用 MechanicSim 源码定义及运行时，替换客户端传输适配层；原工程只读引用。

## 边界

- 仅本地配置可选定启动程序及定义目录，不接受游戏客户端传入命令行。
- 版本、请求序号、实例生命周期校验；单次有界响应；通信在后台线程处理，世界服轮询不阻塞。
- 复用现有 LuaDirector 的验证和任务结算，通过允许列表调用，禁止动态执行 C# 发来的 Lua 文本。
- 原生伤害使用显式 Damage/AoE 接口。SendDamageText 不自动等同真实伤害。自定义状态、模型及 VFX 必须显式映射；无法原生表达的表现报出诊断。
- 现有实例继续原控制器，按副本配置显式启用 C#；源码修改只在新控制器进程编译，当前战斗不被热替换。
- 原项目 RaidManager.Instance 为单例，所以进程隔离是实例隔离的必要条件。

## 验证

原始定义编译、控制器示例端到端、实际动作映射、错误命令拒绝、跨轮次丢弃、退出/超时取消以及旧副本回归。新绝本机制迁移和实机显示验收仍在原方案中跟踪。
