# 战术板分享

国服客户端 `2026.11.03.0000.0000` 使用客户端内部的 Tofu 协议。单张战术板和文件夹可发给小队，客户端根据收件回执决定是否定向重发。实时分享使用同一份压缩快照启动，只有主持人可以发送编辑增量。队员中途加入或需要重新同步时，World 转交快照请求，由主持人的客户端发送当时的战术板。主持人结束、退队、断线或小队解散后，World 清理会话。

| 方向 | Opcode | 用途 |
| --- | --- | --- |
| 客户端 → World | 288 | 初始快照或指定收件人的快照 |
| 客户端 → World | 834 | 收件回执，编号 0 请求实时快照 |
| 客户端 → World | 644 | 编辑增量 |
| 客户端 → World | 386 | 操作 0 结束，操作 3 请求重新同步 |
| World → 客户端 | 712 | 携带真实发送者角色 ID 的快照 |
| World → 客户端 | 714 | 携带接收者和板编号的回执 |
| World → 客户端 | 373 | 编辑增量 |
| World → 客户端 | 112 | 通知当前主持人或结束实时分享 |

IDA 中，`0x140BD7D90` 发送快照，`0x140BD5720` 接收快照并按文件夹序号回复。主持人通知和快照回执分别由 `0x140BC8DB0` 和 `0x140BC9030` 处理。关闭与重新同步分别由 `0x140BC8BB0`、`0x140BD79F0` 发出。快照 CRC32 覆盖 1040 字节压缩区，增量 CRC32 覆盖载荷偏移 8 起的 56 字节。

服务端测试覆盖普通广播、定向重发、文件夹序号、主持人权限、迟到和失步恢复、主持人关闭或离队。国服双客户端还需实机确认接收提示、文件夹导入以及编辑后的画面同步。

主持人的客户端在发送首张实时快照前已写入自己的角色 ID，由菜单回调直接进入编辑器。World 将首张快照转发给队员，避免向主持人重复发送 Opcode 112，触发第二次界面切换。队员中途加入或请求刷新时仍会收到必要的主持人通知。
