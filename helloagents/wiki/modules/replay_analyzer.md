# 独立 Windows 录像分析工具

## 入口与范围

- 源码：`tools/ReplayAnalyzer`；发布：`target/ReplayAnalyzer-1.1.0/ReplayAnalyzer.exe`。
- .NET 10 WinForms；独立解析库和无第三方依赖的控制台回归。现有服务器、游戏与 MechanicSim 不参与运行。
- 支持 `FFXIVREPLAY v5`、当前国服录像 build `14101351`。未知 build、错误魔数、短负载、越界目标数和非有限浮点数会拒绝载入。
- 原始录像只读；忽略录制者 CID、玩家名称和聊天内容，界面使用 `P1` 等匿名演员标识。报告保留临时实体 ID、录像文件名和 SHA，方便回查；工程另外保存本地路径。

## 使用流程

1. 双击 EXE，导入多份 `.dat`，或者打开随附的 `示例工程.json`。也可拖入录像、导入目录第一层录像，或用命令行参数传入工程/录像路径。同 SHA 的重复文件跳过。
2. 在左侧选择录像或阶段。默认自动过滤玩家及其召唤物技能、高频移动；上方可开启。搜索支持技能名、技能 ID、演员、参数和人工备注；数字技能 ID 同时展示关联候选。
3. “事件时间轴”显示原始顺序、相对/绝对时间；五条色带分别表示读条、判定、地图、演出和物件，点击定位最近事件。
4. “技能与演出”汇总调用次数、判定、预兆配置与地图/演出关联。选择技能后在下方查看资源路径和关联依据；双击转到事件筛选。
5. “地图 / 物件”展示 MapEffect、初始化、EObj/NPC 创建与移除、EObj 动画。选择左侧阶段后，详情列出进入该阶段前最后已知 MapEffect 状态；完整重置中的零状态不逐项列出。
6. 选中事件，通过“阶段 / 锚点”拆分、重命名、设置相对零点、向前合并或恢复自动章节。跨录像使用同一阶段名称，并把对应技能事件设为锚点。
7. “合并对照”按副本、build、阶段名、事件签名和锚点时间聚合，默认允许 1.5 秒误差，可调 0–30 秒。每组最多包含同一录像同一阶段中的一次观察，保留每次重复调用。双击返回首个原始记录，详情保留所有来源、偏移和位置。
8. 右键事件可人工分类、关联技能 ID、添加依据。人工整理参与技能统计和合并签名，同时保留原始包分类；保存工程后恢复。
9. “资源字典 · 全录像”查看 RSV/RSF。该页故意显示整份录像，避免阶段筛选遮掉入场资源；仍可用搜索框筛选资源键和值。

## 导出和恢复

### 单独机制分组（1.1）

打开“机制分组 · 多录像”，工具按相同副本、build、阶段名称和中文技能名自动整理。默认过滤玩家本体和沿 Owner 链识别的召唤物技能；同一个技能 ID 由 Boss 使用时仍保留，不使用技能黑名单误删。玩家身上收到的 Boss 状态、标记等保留为机制证据。

- 同名机制的不同技能 ID 合并展示，保留读条、判定、演出、MapEffect/EObj 候选与全部重复调用。每条观察仍有原始文件、偏移、时间和关联置信度。
- Ctrl / Shift 多选机制行，右键“合并选中机制 / 重命名”可把不同名称的技能归为自定义机制；也可在事件表右键“归入指定机制组”。人工命名随工程保存。
- 双击机制行，在事件表只显示当前录像中的该机制及关联事件；“清除”返回完整筛选范围。
- “当前机制分组 CSV”导出当前副本/阶段/名称筛选后的组；“选中的单独机制 JSON”导出选中机制，包含该组所有来源和调用。机制页范围由左侧副本、阶段和名称/ID 搜索决定，不应用事件类别或绝对秒过滤。
- 自动同名不等于完整机制逻辑相同；通用/未知名称按 ID 保留区别，仍可人工调整。阶段名称不同则保留为不同阶段中的组，不跨阶段强行折叠。

八份真实录像整理出 639 个机制组，其中 189 组包含多个技能 ID；自动回归验证组内没有玩家/召唤物技能，且支持跨录像同名阶段整理。完整报告仍保留原始事件供审计，自动过滤应用于默认界面、技能汇总与机制分组。

### 文件类型

- **工程 JSON**：路径、SHA、阶段、锚点、人工标注及合并误差。不包含原始录像。恢复时核对 SHA；阶段有重叠、空隙或覆盖不全会拒绝应用。
- **当前筛选 CSV**：保留表格当前排序及筛选，包含阶段、时间、Opcode、偏移、原始/人工分类、技能、参数、目标效果和备注。UTF-8 BOM 用于兼容 Excel。
- **合并 CSV**：全部已载入录像的对照结果，每组附全部原始来源，不仅导出当前页面筛选。
- **完整 JSON**：所有记录、演员、阶段初始 MapEffect、技能资源、关联证据、人工标注、未知包统计及合并项。完整报告可能较大。
- **资源 JSON**：全部 RSV/RSF 和录像时刻，供分析使用；它不是服务器资源清单，不能不经转换直接交给服务器加载。

工程和报告用途不同。打开工程必须使用工具保存的工程文件；报告只用于进一步分析。扩展名验证防止把报告写到 `.dat` 路径。

## 解析与证据

协议配置在 `Data/protocol.json`，资源快照在 `Data/catalog.json`。可用“资源表目录”重新加载国服 CSV；Action 的资源字段按 CSV 类型行定位，避免旧表头与真实列错位。

解析包括 NPC/EObj 生命周期、ActorMove/ActorSetPos、读条、五种容量的 ActionEffect、状态快照与增减、MapEffect/整表初始化、Director、BGM、天气、动画/模型状态、目标标记、连线、可见性、演员 ActionTimeline、RSV 和 RSF。

判定和演出不是互斥分类。动作效果中能观察到的伤害、治疗、状态、击退等标记为结算；未知效果单独标记。无伤害/无目标不能证明技能是纯演出。资源表中的 Omen、VFX、ActionTimeline 只能证明配置引用，不能证明该次屏幕上一定显示。

同演员、同技能的读条与动作效果关联，以及相同演员的动画资源引用、相同状态和目标的效果匹配，标为高置信度；同演员邻近控制为中；MapEffect/EObj 等只有时间邻近证据时为低。只在相同阶段内寻找候选。人工关联有独立标记，不会改写原始动作 ID。

原始章节是战斗/过场区间候选，不等于自动识别所有 P1/P2。五个已有最终阶段在 `phase-presets.json` 中按录像 SHA 精确匹配：龙诗 P7、光暗 P5、欧米茄 P6、绝亚 P4、妖星 P5。其他阶段可手动整理。

未知 Opcode 和不支持的 ActorControl 类别保留计数，不导出未知完整负载。工具不能从录像单独恢复服务端所有几何、随机、条件判定；不会把邻近事件当成已证明的因果。升级游戏后，不能只把新 build 写进白名单就假定旧偏移仍兼容，须重新核对协议和 CSV。

## 模块

- `Core/ReplayReader.cs`：有界解析与匿名演员索引。
- `Core/GameCatalog.cs`：CSV、RSV 名称及预兆/动画/VFX 引用。
- `Core/Analysis.cs`：阶段、关联、技能汇总与跨录像合并。
- `Core/WorkspaceFiles.cs`：工程校验、CSV/JSON 导出。
- `Desktop/MainForm.cs`、`Controls.cs`：中文工作台、虚拟表、时间轴。
- `Tests/Program.cs`：合成损坏输入、语义、工程、合并及真实录像回归。
