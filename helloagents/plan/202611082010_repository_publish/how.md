# 技术设计：整理与发布工作区

## 技术方案
- 使用 Git 保留现有 master 和全部历史；新增 `small-miao` 远程，不覆盖 origin/upstream 地址。
- 已比较直接推送、另建分支和合并后推送：直接推送无法快进；另建分支不会更新目标默认分支，因此采用合并后普通推送。
- 先审查候选文件及大小、敏感信息模式，再暂存提交；排除 `.vs`、`bin`、`obj`、Python 缓存和环境文件。
- 若远程 master 有新增提交，获取并合并后重新验证，不使用强制推送。

## 安全与性能
- 不修改本地运行配置，不提交数据库或凭据，不执行部署或重启服务器。
- 保留工具内嵌资源目录快照与已归档源码，构建缓存通过忽略规则保留在本地。

## 测试与发布
- 执行 Git 差异检查、敏感信息模式扫描、文件大小检查。
- 运行世界服测试、EncounterHost 回归和 ReplayAnalyzer 回归；合并影响代码时再次验证。
- 更新知识库，将方案迁移至历史后提交；推送并核对远程提交 ID。
