# 技术设计

扩展现有录像提取器、Lua 控制器和原生物件接口；保留原始录像，输出匿名演员别名。优先复用现有框架，避免另建独立录像播放器而无法处理实时玩家行为。

- 音乐：对照客户端 IDA 与正常 EventScene 参数，恢复正确的入场 BGM/过场结束移交，区分事件通道与副本通道。
- 场景：提取动态 EObj 的生成、方向、参数和删除；由当前实例分配 ID 和客户端槽位，支持死亡重置清理。
- 机制：以原始动作、控制消息和攻略交叉校验，击杀反馈驱动死亡演出，失败分支依据实际存活状态。
- 新副本：先核实录像版本、地图、最终阶段起止点及资料；不将未知机制假装为已实现。

安全：不修改游戏进程内存、客户端文件或原始录像；不保存玩家身份；服务器升级保留二进制备份。验证覆盖提取保真、实时成功/失败/重置、协议长度、世界库回归和实际进程健康。

## 控制方式调整

用户追加要求参考 `D:/Code/MechanicSim-Master/Script/Definitions`，不止拆文件，还要采用直观的定义式控制。保持 Kawari 的 Rust/Lua 原生协议，将手写定义分为 Actions（规则与实时事件）、Statuses（原生状态和生命周期）、Timelines（阶段及具名节点）。节点支持进入/更新/退出、时长、条件及超时；录像仅为节点提供原生表现素材。击杀、爆碎、人数判定和通关不由录像时间自动决定。

Windows 原生 Lua `dofile` 不接受本机代码页之外的 UTF-8 中文路径，已复现 Illegal byte sequence。模块文件名使用 ASCII，名称、说明、节点展示继续为中文。重构过程中出现过入场脚本加载失败，须先恢复并复验龙诗；后续应在独立脚本发布目录验证完成再切换，防止运行服读取半成品。
